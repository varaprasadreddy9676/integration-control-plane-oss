INTEGRATION GATEWAY · WORKFLOW CANVAS

A precision instrument for deliveries

The canvas is drawn from the engine's rules, not by hand. Every branch it shows can happen; every branch that can happen is shown. Colour is kept for selection, actions and meaningful status.

Node anatomy

One shape for every step: 256 × 80, radius 10, one hairline border. The type shows in the icon tile and its tint only; the border belongs to state.

  1. Icon tile: the type, tinted at 10% (16% dark).
  2. Eyebrow: type · where it runs (Before send, Later…).
  3. Title: the name the user chose.
  4. Summary: one useful fact in mono: endpoint, condition, schedule.
  5. Status: dot + word + metric (212 ms, ×3, READ). Never colour alone.
  6. Ports: in at the top, out at the bottom; ends have no out port.

Connectors

  • Orthogonal, 1.5 px, filled head. The main path runs straight down; alternatives leave sideways to the right.
  • A label sits at the branch's source end, 8 px clear of every line, with its 24 h count in mono.
  • Retry loops go round the outside, dashed, back to the top of the attempt: a retry runs everything again.
  • Two lines into one edge meet it at a third and two thirds, never on top of each other.
  • Links are never drawn by hand, so a wrong one cannot exist.
